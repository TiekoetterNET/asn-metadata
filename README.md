# ASN metadata

This repository maintains a small, machine-readable metadata database for the
autonomous systems used by a BGP graph and peer list. It intentionally contains
metadata only; routing policy, Tier-1 lists, graph templates, and web assets
belong in the topology application's repository.

## Data files

- `data/requested-asns.json` is a local fixture and initialization example. The
  Actions workflows fetch the current list directly from the webserver instead
  of modifying this file.
- `data/asn-metadata.json` is generated by GitHub Actions. Each ASN is keyed as a
  string and contains its RDAP name, organization, country code, English
  country name, flag, and lookup timestamps.

Example generated record:

```json
{
  "174": {
    "as_name": "COGENT-174",
    "org_name": "Cogent Communications",
    "country": "US",
    "country_name": "United States",
    "flag": "🇺🇸",
    "last_attempt": "2026-09-01T16:00:00Z",
    "last_success": "2026-09-01T16:00:00Z"
  }
}
```

When a lookup fails, `last_attempt` and a short `error` are recorded while all
previously successful metadata, including `last_success`, is retained. A later
incremental run retries records that have never completed successfully.

## Automation

Both workflows fetch the requested ASN set from
`https://www.tiekoetter.net/asn-metadata/requested-asns.json`. The endpoint must
return a JSON array of integer ASNs. Ordering and duplicate entries are
normalized in memory; the checked-in fixture is not overwritten.

`update-metadata.yml` fetches that endpoint every six hours and resolves only
new or incomplete entries. `refresh-metadata.yml` independently fetches it
every Monday at 03:17 UTC and refreshes every requested or previously known
ASN. Both workflows commit only `data/asn-metadata.json` when it changes.

The server can periodically download the raw `data/asn-metadata.json` file and
cache it locally.

## Local use

Python 3.10 or newer is required.

```shell
python -m pip install -r requirements.txt
python scripts/update_metadata.py
```

Local runs use the checked-in fixture by default. To use the webserver input:

```shell
python scripts/update_metadata.py \
  --requested-url \
  "https://www.tiekoetter.net/asn-metadata/requested-asns.json"
```

To refresh all existing records as well as requested ASNs:

```shell
python scripts/update_metadata.py --refresh-all
```

The script discovers the authoritative RDAP service for each ASN through
IANA's RDAP bootstrap registry. Input is validated and output is written
atomically in numeric ASN order.
